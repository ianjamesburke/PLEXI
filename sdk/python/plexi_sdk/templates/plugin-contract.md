## Module Layout

- `main.py` — thin wiring only: `init` returns `tools.expose()`, `update` calls `tools.dispatch(event)` first and then handles keys/UI actions, `view` delegates to `plugin.ui.build_view(...)`. Do not grow logic here.
- `plugin/tools.py` — assistant-callable tools as plain Python functions registered with `@tools.tool(...)` (`from plexi_sdk import tools`). No UI code.
- `plugin/ui.py` — pure view builders (`Column`, `SurfaceHeader`, `Text`, `FooterKeys`, ...). No effects.
- `plugin/__init__.py` — marks the plugin package. The package avoids a bare root-level `tools.py`, which would shadow `plexi_sdk.tools`. Add further modules there and import them from `main.py`.

## Build Loop

- Use TDD. Add or update tests for every behavior change before changing plugin code.
- Run `plexi plugin test .` regularly while editing.
- Keep the root semantic view shell padded: `Column([...], grow=True, padding=SPACE_MD)` or larger. Do not use `padding=0` on the root shell; surface headers and footers render full-bleed while body/action/footer content stays inset.
- Before done, run the full gate: `PLEXI_CHANNEL=alpha plexi plugin check . --png-dir render-output/check` or use the matching PR build, for example `PLEXI_CHANNEL=pr-123 plexi plugin check . --png-dir render-output/check` or `plexi-pr-123 plugin check . --png-dir render-output/check`.
- Render JSON and PNG artifacts with an explicit alpha or PR channel. Use seed state when behavior depends on state: `PLEXI_CHANNEL=alpha plexi view render . --state fixtures/state.json` and `PLEXI_CHANNEL=alpha plexi view render . --png --output render-output/shot.png`.
- Exercise behavior through pane actions and keys, not only by reading code: `plexi pane action <pane-id> <handler-id>` and `plexi pane key <pane-id> <key>`.
- Hot reload is part of the dev loop. New plugins set `watch = true`; after `plexi view open .`, edit source and verify the same pane id updates without reopening by checking `plexi pane state <pane-id>` and the `hot_reload` lines in the host log.
- When probing a real host from outside the matching Plexi pane, set the matching socket explicitly: `PLEXI_SOCKET=$HOME/.plexi-alpha/notify.sock PLEXI_CHANNEL=alpha plexi ...` or `PLEXI_SOCKET=$HOME/.plexi-pr-N/notify.sock PLEXI_CHANNEL=pr-N plexi ...`.
- Inspect runtime state and logs when validating: `plexi pane state <pane-id>` and `~/.plexi-alpha/plexi.log` or the matching `~/.plexi-pr-N/plexi.log`.
- Keep source, tests, fixtures, and this metadata as durable truth. Do not record progress in this file.

## Logging

Use SDK log levels intentionally:

- `log.debug` for detailed state, render, or event diagnostics.
- `log.info` for init, user actions, and state transitions.
- `log.warn` for recoverable fallbacks or ignored input.
- `log.error` for unrecoverable failures before returning or surfacing the failure.
