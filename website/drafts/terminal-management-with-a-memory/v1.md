The terminal did not fail.

It stayed exactly what it was: a prompt, a process, and scrollback.

The problem is that our work outgrew that shape.

Today a terminal session is not just "run a command." It is a dev server, a test watcher, an AI agent, a log stream, a deployment, a scratch note, a GitHub issue, a database shell, a local app, and a half-finished idea you need to come back to later.

Most terminals manage that with tabs.

Plexi manages it with memory.

## Panes, not tabs

Tabs hide work.

Panes expose it.

Plexi uses a tiling layout. You split the current pane, move focus with the keyboard, swap panes, zoom into one pane, close a pane, or open a new terminal beside the one you are using.

That is the visible part.

The more important part is that panes are addressable.

Plexi can list panes as JSON. It can focus a pane by ID. It can capture output. It can send a command to a pane. It can send a keypress. It can rename a pane.

This matters because work should not depend on "the second tab after the logs tab."

It should have handles.

`api server`

`tests`

`claude-code`

`logs`

`review notes`

Once panes have names and IDs, the workspace becomes something a human can scan and an agent can script.

## Contexts, not piles

Plexi has contexts.

A context is a project/workspace scope tied to panes, roots, descriptions, app instances, and secrets. You can create a context, open one at a path, describe it, list contexts, zoom into a subcontext, zoom out, or push the focused pane into a new subcontext.

That last bit is important.

Real work branches.

You start fixing a bug, notice a bad test helper, then find a docs problem, then realize there is a product idea hiding underneath it. A normal terminal gives you two choices: chase the tangent or lose it.

Plexi gives you a third option: make a subcontext.

Keep the pane alive. Give the tangent a name. Park the thought in the workspace instead of in your head.

The point is not to make project management software out of your terminal.

The point is to stop using your memory as the project manager.

## Notes where the work happens

Plexi has Quick Note.

Press the shortcut, write the thought, route it, keep going.

That sounds like a small feature until you notice how much work disappears because capture is too expensive.

The terminal is full of moments like:

- "This needs a follow-up issue."
- "Remember to check the logs after the next run."
- "This command worked."
- "This approach failed."
- "Ask Claude to turn this into a script."
- "Make this a reusable app later."

When capture means opening another app, the note loses to momentum.

In Plexi, notes belong beside the process that created them. The backlog is local. Scratchpad notes live on disk. The notes command can list or open them from the terminal.

The work leaves residue you can actually use.

## Notifications instead of staring

Terminal work often means waiting.

Waiting for tests.

Waiting for a build.

Waiting for a deploy.

Waiting for an agent.

Waiting for a script that may or may not ask you a question.

Plexi has a notification bus. A terminal process, app, or CLI command can send a notification into the UI. It can include a body, priority, choices, scope, and host actions.

That means terminal work can become interactive without growing a whole interface.

A deploy can say "review before promoting."

A script can ask "open PR or skip?"

A background process can tell you "done" without taking over your screen.

You stop polling your terminal like a security camera.

## Apps inside the workspace

Some terminal problems want UI.

CSV files are easier in a table. Logs are easier with color and filtering. Permissions are easier in a focused surface. GitHub issues are easier when you can browse them next to the repo.

Plexi app panes handle that.

Apps are PGAP processes. They declare capabilities. They render into panes. They can notify, log, ask for secrets, query AI, and interact with the host through a typed protocol.

That gives Plexi a clean answer to a common workflow problem:

"I need something more visual than the terminal, but I do not want to leave the workspace."

Open an app pane.

Build a small app.

Wrap a CLI.

Wrap an MCP server.

Keep the thing where the work already is.

## Secrets with scope

Terminal management is not just layout.

It is also environment.

Most terminals leave secrets to shell startup files, ad hoc `.env` files, or whatever a tool happens to read. Plexi has a built-in secret CLI backed by the system keychain:

```sh
plexi secret set OPENROUTER_API_KEY
plexi secret list
plexi secret delete OPENROUTER_API_KEY
```

Secrets can be workspace-scoped or global. The project value wins before falling back to global. Apps request secret access through a capability.

That is terminal management with consequences.

The shape of the workspace includes what it is allowed to know.

## Agent visibility

Plexi has agent commands for workspace agent definitions and Claude Code hooks.

An agent can report whether it is working, blocked, or idle. Plexi can show agent status for panes. Claude Code hooks can report lifecycle events into Plexi.

This is where terminal management starts to turn into agent management.

Once panes are named, contexts are scoped, output is capturable, notes are local, notifications are routable, and agent state is visible, you can supervise more work without manually staring at everything.

That is the daily-driver reason Plexi matters.

It reduces the amount of state you have to personally remember.

## The before and after

Before:

Your terminal has tabs. Your tabs have scrollback. Your secrets are in shell files. Your notes live somewhere else. Your agents are invisible unless you are watching their pane. Your work is organized by your memory.

After:

Your terminal has named panes. Your panes live in contexts. Contexts can have subcontexts. Notes get captured in place. Notifications come back to the host. Apps render beside shells. Secrets are scoped. Agents can report state.

This is not terminal decoration.

It is terminal management with a memory.

That is what Plexi is for.
