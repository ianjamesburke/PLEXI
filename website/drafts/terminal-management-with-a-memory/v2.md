Your terminal has amnesia.

It remembers scrollback. It remembers command history. It might remember your tabs if the app restores them after a restart.

But it does not remember what the work means.

It does not know that one pane is the server, one is the test runner, one is Claude, one is logs, and one is the weird tangent you are not ready to close. It does not know that this project uses a different API key than that project. It does not know that the command which just finished should notify you. It does not know that the thought you had during the build belongs in the backlog.

It is not stupid.

It is just a terminal.

Plexi is what happens when terminal management grows a memory.

## The day starts clean

You open a project.

One terminal is enough.

You run the app. It fails. You open another terminal for logs. Then one for tests. Then one for git. Then one for Claude Code. Then you split one because you need to compare output. Then a command is running, so you open another because you do not want to interrupt it.

By lunch, the clean workspace is gone.

You have a layout, but you do not have a system.

The difference matters.

A layout is where things are.

A system knows what things are.

## Tabs are where work goes to hide

Tabs feel organized when there are three of them.

At eight, they become a memory test.

Which tab has the server? Which one is safe to close? Which one has the command that failed? Which one has the agent that is waiting for permission? Which one was for the tangent?

Plexi uses panes instead of hiding everything behind a tab strip.

You split the workspace. You navigate by direction. You zoom when you need focus. You rename panes so they say what they are.

But the real difference is that Plexi panes are scriptable.

They have IDs. They can be listed. Their output can be captured. You can send a command or keypress to a pane. You can focus a pane directly.

The workspace becomes legible to you and to agents.

That is the first memory layer.

## Then the project needs a boundary

The next failure is scope.

You think you are working in one project, but your machine has no idea where the work begins and ends.

The terminal inherits your shell. Your shell inherits your dotfiles. Your dotfiles may expose keys or settings meant for something else. Your panes may be in different directories. Your notes may not say which repo they came from.

Plexi has contexts.

A context is a workspace with a root, panes, descriptions, secrets, apps, and child contexts. It can describe the project you are in, not just the folder you started from.

Subcontexts are where this gets useful.

The bug can have a subcontext. The PR review can have a subcontext. The "do not chase this right now" tangent can have a subcontext.

Instead of making your brain hold the shape of the day, Plexi gives the day a shape.

## Then you need to remember something without stopping

This is where most workflows quietly lose information.

You see something important while doing something else.

A flaky test. A better command. A follow-up issue. A sentence for the README. A bug you cannot fix right now. A product idea hiding inside the problem.

If you stop, you lose momentum.

If you do not stop, you lose the thought.

Plexi has Quick Note.

Open it, write the thing, route it, keep moving.

It is not trying to be a second brain app. It is a trapdoor for thoughts that appear while work is already in motion.

That is the second memory layer.

The workspace can remember what you noticed.

## Then a command needs attention later

The terminal is full of work that does not need you now but will need you eventually.

Tests. Builds. Deploys. Agents. Scripts. Downloads. Local servers. Anything that can succeed, fail, or pause for input.

Most terminal setups handle that by making you look.

Look at the pane. Look at the logs. Look at the tab title. Look again just in case.

Plexi has a notification bus.

A command can notify the host. An app can notify the host. A notification can have choices. It can be scoped to a window, a context, or globally.

Now the process can come back to you.

That is the third memory layer.

The workspace can remember to interrupt you.

## Then plain text is the wrong surface

Some terminal work wants to stay text.

Some does not.

A CSV wants a table. Logs want filtering. Permissions want a management surface. GitHub issues want browsing. Todos want state. A tiny project-specific tool wants UI, but not a whole SaaS app and not a browser tab.

Plexi has app panes.

Apps run beside terminals. They speak PGAP. They declare capabilities. They can request secrets, send notifications, log to the host, use AI, and render UI inside the same workspace.

So the answer to "I need a small interface for this" does not have to be "open another app."

It can be "open another pane."

That is the fourth memory layer.

The workspace can remember more than text.

## Then credentials enter the room

Terminal work gets dangerous when secrets are invisible.

You export a key. You put one in `.env`. You paste one into `.zshrc`. You source a private file. Six months later, a tool works because some key is available somewhere, and you are not sure why.

Plexi has workspace-scoped secrets backed by the system keychain.

This is the right question:

"What is this workspace allowed to know?"

Not:

"What did my shell happen to inherit?"

That is the fifth memory layer.

The workspace can remember its credentials without turning every terminal into a secret soup.

## Then agents make everything sharper

All of this mattered before AI agents.

Agents make it unavoidable.

When Claude Code is running, the terminal is no longer just waiting for you to type. Something else is acting. Reading. Editing. Asking. Running tools. Getting blocked. Continuing.

That process needs visibility.

Plexi can install Claude Code hooks and track agent state. It can show which panes have agents that are working, blocked, or idle. It can surround those agents with named panes, scoped contexts, notes, notifications, app surfaces, and secrets.

A normal terminal can run an agent.

Plexi can manage the room the agent is working in.

That is the sixth memory layer.

The workspace can remember who is doing what.

## This is the actual product

Plexi is easy to undersell if you describe it as a terminal.

Yes, it has terminal panes.

But the product is not the prompt.

The product is the memory around the prompt.

Pane names.

Context.

Subcontexts.

Scoped secrets.

Quick notes.

Notifications.

App panes.

Agent state.

Local files.

Host logs.

Permission records.

All the stuff a normal terminal leaves in your head.

That is what Plexi is trying to take seriously.

Not because terminals are bad.

Because terminals won.

Now they need to grow up.
