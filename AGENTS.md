## Purpose

`CLAUDE.md` is a symlink to this file. Cross-cutting rules for all agents. Domain-specific contracts live in each directory's own `AGENTS.md`.

Plexi is an agent operating system. Judge every change by whether it moves an agent closer to operating the machine *through* Plexi: native surfaces instead of OS apps, brokered capability instead of raw access, structured state instead of scraped output. An agent inside a pane reaches for the Plexi surface first and treats the OS as the fallback.

Before editing any file, read the `AGENTS.md` in its directory if one exists. Child rules add to this file; they never override it.

## Branches

`alpha` is the starting branch for all feature branches, worktrees, and PRs. Never branch from `main` or `beta`. Feature branch naming: `feature/<issue-number>-short-description`.
Three standing worktrees always exist: `alpha`, `beta`, `main`. Never remove them during cleanup.

## Git Rules

Never add `Co-Authored-By: Claude ...` trailers. Never push directly to `main` or `beta`. Never pass `--delete-branch` to `gh pr merge`.

## Tasks and Issues

Always use the `/create-stint` skill to create tasks. Never create stint tasks or GitHub issues manually.
`.stint/` is git-ignored by design. Validate task state with `stint check`, `stint list`, `stint show <id>`, and `stint status`.

## Planning

Read the relevant PRM first. Use `stint next` for the next claimable task. Stint tasks are the primary implementation tickets; GitHub issues are optional. Pipeline labels (`pipeline:implement`, `pipeline:open-pr`, `pipeline:validate`, `pipeline:merge`) track live state.

## Logging

Log file: `~/.plexi-<channel>/plexi.log` (level set in `config.toml`).
Every new feature must be instrumented: no new capability, command, or user-visible behavior ships without at least one `info`-level trace.

## Testing

**Mandatory self-validation contract: [`src/testing/TESTING.md`](src/testing/TESTING.md).** Follow its phase-aware gates before pushing, integrating, or installing.
- Test-first for host logic. Define done by the test, not the code. No partial merges.
- Observable state belongs in TOML scenes; return values and invariants belong in Rust tests.
- `linux` CI is advisory (runs with `continue-on-error`), not a merge gate. Record Linux-only failures in PR body and `TRUTH.md`.
- Host UI changes: visual review via harness screenshot test is mandatory before shipping.

## Panic Discipline

`todo!()` and `unimplemented!()` are banned outside `#[cfg(test)]` (enforced by `#![deny(clippy::todo, clippy::unimplemented)]`). Factory-returned impls must never panic in trait methods.

## Error Handling

Try-catch all I/O, network, external API calls. Log where + what failed. Never swallow errors. Propagate unrecoverable failures.

## Issue Visibility Before Work

Reproduce the bug before fixing it. Preferred: a failing `HostHarness` test. Acceptable: a targeted `log::info!` confirmed in `plexi.log`. If you can't reproduce or instrument it, stop and flag it.

## Issue Prior Attempts

Document failures in the issue **body** under `## Prior Attempts`, not in comments. Comments are invisible to `gh issue view` without `--comments`.

## Session Velocity

- **Sequential child agents only.** Never parallel in one worktree.
- **Ideas become stint tasks, not tangents.**
- **Direct-to-alpha when user is watching.**
- **Own the build.** If your change breaks something, fix it.

## Documentation Rule

Every fact lives in exactly one place. Other files reference it; they never restate it.
- **No volatile numbers in docs:** Never cite line numbers, file offsets, or item counts. Reference code by symbol name (`builtin_factory`); describe sets by defining source (`packs/core.toml`).
- **One progress tracker per unit of work:** Work lives in a stint task — never in a GitHub issue or spec doc. No checklists or status tables in PRMs.

## Traps

- **macOS child PID lookup:** `proc_listchildpids` returns `EFAULT` on Sonoma. Use `pgrep -P <pid>` instead.
- **Auto-committing scripts:** `cargo run -p gen_config_docs > website/src/content/docs/config.md` to regenerate config docs without `just`'s auto-commit/push.
- **Stale git index:** Run `git update-index --refresh` if `git status --porcelain` shows false-dirty files.
- **macOS platform timing:** Add a throwaway `log::info!()` to observe actual runtime values on the first frame instead of guessing callback order.
- **Command handler data:** Store all required data in command fields; never look up from ambient state at dispatch time.
- **`#[cfg(unix)]` removal:** Grep for `set_mode`, `PermissionsExt`, and `0o755` across test files when removing unix blocks.
- **Issue-referenced code:** Grep `alpha` before implementing; referenced functions may have moved or been deleted.
- **Context targeting:** `create_page_at` takes an explicit `context_id`. Never switch `active_window` or `router.active` to steer it.
- **Thread data through arguments:** Pass explicit parameters instead of mutating global focus/active state.
- **CLI context:** Plexi CLI almost always runs inside a Plexi pane with `PLEXI_SOCKET` set.
- **Runtime topology & channels:** Agent panes run under `plexi-beta`. To target a specific channel, always use the channel-named shim (`plexi-alpha`, `plexi-pr-<N>`) or explicit `env PLEXI_CHANNEL=<ch> plexi ...` — never rely on bare `plexi` or inherited `PLEXI_SOCKET`.
- **Parallel worktrees:** When rebasing same-wave branch conflicts on shared files, keep the most complete fix.
- **Login shell probes:** Host-spawned probes must be setsid-isolated (no controlling TTY, stdin=/dev/null, capture stdio). Use `run_login_shell_probe` in `src/host/shell.rs`.
- **egui repaint scheduling:** Add `InputState::predicted_dt` to remaining delay; avoid literal zero-delay requests which cause immediate repaint loops.
- **macOS App Nap:** Non-frontmost idle host gets napped without `NSProcessInfo` activity (`platform::app_nap::disable_app_nap`).
- **Service external I/O in `App::logic`, never `App::ui`:** eframe skips `App::ui` entirely when the window is hidden or occluded. All external drains (pane IPC, spawn queue, PTY events, shutdown, event-bus, screenshots, Python runtimes) must live in `App::logic`.
- **App servicing axes:** `service_app_commands` in `App::logic` handles occluded windows; `AppRuntime::background_tick` handles inactive contexts. Both are required.
- **`rustfmt` on mod files:** `rustfmt src/main.rs` reformats all reachable modules. Format only leaf files touched.
- **`cargo test` vs `just build`:** Test builds don't enforce dead-code warnings or non-test cfg blocks. Always run `just build` before push.
- **Window close vs process exit:** Closing the window does not end the process. Every quit path must finish in `app::quit::exit_host`.
- **Mid-frame exit skips `App::on_exit`:** Any exit outside `on_exit` (like `plexi host stop`) must explicitly invoke cleanups (e.g. `bank_final_focus_segment`).
- **UI thread profiling:** Drag/resize stutter in `App::ui` is invisible to logic heartbeat. Use `PLEXI_UI_PROFILE=1` to profile.
- **`stint add` race:** Create tasks sequentially; parallel invocations can cross-assign task IDs.
- **Filesystem walks on UI thread:** Picker walks must run in background threads and drain via `App::logic`, never block `App::ui`.

## Architecture

**HostModel** is a pure state machine with zero egui dependency. Commands in, effects out. All business logic lives here. The renderer reads state and paints — never owns logic.

## Inter-Pane Communication

Three disjoint planes with sanctioned transports:
- **Structured app-to-app data → event bus:** `DeclareEventStreams` / `EmitEvent` / `SubscribeAppEvents` (or `PipeOpenDirected` for exclusive duplex JSON channel).
- **Bulk binary data → typed pipes** (`src/host/typed_pipes.rs`): Unix socket + ring buffer for audio/video/MIDI frames.
- **Human-trust PTY injection → `plexi pane send`:** For human terminal driving only. Never route app-to-app data through PTY injection.

## Capturing Host State

Use `plexi host screenshot [--pane <id>] [--output <path>]` to capture real host pixels. Never use macOS `screencapture`. For semantic state, use `plexi pane state <id>`. For headless app preview, use `plexi app render . --png`.

## General Rules

- When the user reports a bug, fix what they asked for first.
- App/host state is reached through SDK tools or CLI, never a `~/.plexi*` path.
- Never use `#[allow(dead_code)]` or `#[allow(unused)]`. Delete or wire up.
- Follow the mandatory self-validation contract above after work; bare `cargo build` is not an installable-build gate.
- **Failed PR reset:** close the PR, revert worktree, comment on the issue, re-label `ready`, start fresh.
