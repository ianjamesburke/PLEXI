## How the binary was installed

```bash
bash scripts/install.sh --from-source verify2686
```

That is the release path (`just build`, `-D warnings`). Binary version `plexi 0.3.5`, build id `88abb95a079ba443ee30ebf5e8dbd47ac1e9aa8f-8eb6e4449725f4a9d952290dfb1c9f9fad71cceab976a7831565cd38fcb8d0b9`. `PLEXI_BUILD_TEST_CHANNEL` was unset, so this is not a test-channel binary.

The Assistant and the host MCP server are release-gated to basename `plexi-alpha`, `plexi-beta`, or `plexi-pr-<digits>` (`feature_enabled_for_channel` in `src/release.rs`). The same generation binary was copied to `~/.local/bin/plexi-beta` and run as channel `beta` with profile `~/.plexi-beta`. `PLEXI_SDK_PATH` pointed at the package `resources/sdk`. The package wasm bundle was symlinked to `~/.plexi/wasm-bundles` because a renamed copy is not the executable recorded in `package.json`, so `distribution::resources()` does not see it.

Host: `plexi-beta host start --ephemeral --timeout-secs 90` on `Xvfb :99` (1400x900), `WGPU_BACKEND=vulkan`, lavapipe (`llvmpipe`). Chess was installed from this commit (`app install apps/chess --yes`). The model was the local mock in `docs/verify/pr-2686-mock-model.py` (`[ai] backend = "local"`, `base_url = http://127.0.0.1:8765`). No API key.

A first pass under the name `plexi-verify2686` already showed checks 1, 2, and 4 behaving the same way, and logged:


Runner: `docs/verify/pr-2686-run.sh`. `app call` prints a successful body on stdout and a refusal as `error: {json}` on stderr. Both were scored.

## 8. PASS — personal sign-off cannot be clicked through

Linux, so there is no Secure Enclave. Config had `fallback = "refuse"` and `[permissions] default_posture = "allow"` with the probe tool on `allow`. Fixture app `signoff-probe` tool `signoff.export` is `requires="personal_signoff"`, `signoff="each_time"`.

Startup:

```text
personal_signoff: fallback=refuse
personal_signoff: installed signer refused (not Touch ID)
```

In-pane call `signoff.export` `{"amount":1}` after the guest logged `signoff-probe: init`:

```text
personal_signoff: signoff-probe__signoff.export requires each_time (manifest)
permission_monitor: admit ... -> ask signoff=each_time
personal_signoff: Secure Enclave is not available on this build (not Touch ID); fallback refuse
personal_signoff: personal_signoff_refused pending=req_3ddce1fb-a07e-4b44-973c-2ae1109cb152
```

Reply: `permission_denied`, `state: denied`. The posture allow did not authorize it. The guest did not log an export.

## 9. PASS — 20 concurrent calls

Twenty `chess.play` calls (`operation_id` `load-1` .. `load-20`, move `a2a3`) were started together from one terminal pane.

All 20 returned `permission_required` (stderr). None hung. `permission-audit.jsonl` has exactly one row per `load-N`. After `assistant permission resolve <id> --choice deny` on each of those pendings, a following `permission list` had zero `load-*` / `a2a3` rows left. No deadlock.

## What to fix

Nothing in these nine checks failed on the installed binary.

Two limits of this run, not gate bypasses:

- A channel whose basename is not `alpha`, `beta`, or `pr-<digits>` never starts the Assistant or the host MCP server. Repro: `install.sh --from-source verify2686`, then `plexi-verify2686 app open assistant`. The log line is `assistant is not enabled on this release channel`. Dogfood of those two ingresses has to use `plexi-alpha`, `plexi-beta`, or `plexi-pr-<N>`.
- Touch ID was not exercised. Repro for the Mac half is the manual section of `docs/personal-signoff.md`.
