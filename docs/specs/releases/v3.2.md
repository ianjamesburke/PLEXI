## Release-level human verification

- [ ] Create two workspaces: `~/work-test/` and `~/personal-test/`. `plexi workspace init` in each. Verify `.plexi/workspace.toml` with unique UUIDs and empty `secrets.toml` exist.
- [ ] In `~/work-test/.plexi/apps/`, drop a test app. Launch Plexi from that dir — app appears. Launch from `~/personal-test/` — app does NOT appear.
- [ ] Same test for `.plexi/agents/`.
- [ ] Route `OPENAI_API_KEY` to two different Keychain entries in the two workspaces. Run the same app in each. App reports two different key values via debug log. Same canonical name, different secret.
- [ ] In one workspace, route the same canonical secret to two different Keychain entries for two different apps. Both apps run, each gets its routed key.
- [ ] Set `fallback = false` in workspace; remove the explicit route for a required secret. App reports clear missing-secret error in-pane (no silent fallback).
- [ ] Set `fallback = true`; route a user-scope key. App reads through the fallback. Log entry confirms fallback path was used.
- [ ] Use Cmd+N and Cmd+Shift+N per the new spec. Pane creation matches expectations.
- [ ] Set up 6 panes in a complex layout. Use Shift+Cmd+H/J/K/L to jump focus in all four directions. Focus lands on the geometrically-correct neighbor every time.
- [ ] Copy text from terminal pane A. Paste into terminal pane B. Verify content matches exactly, including special characters and multi-line.
- [ ] Copy from a Plexi pane. Paste into an external macOS app. Works.
- [ ] Copy from external app. Paste into Plexi pane. Works.
- [ ] Use the Installer App to install a new app. App appears in the workspace's app list immediately, no host restart.
- [ ] **#308 Phase 1 — workspace adoption + config merge.** Drop `[log]\nlevel = "debug"\n` into a workspace's `.plexi/config.toml`. Launch `plexi-alpha /path/to/that/workspace` and run `workspace-config-tester` — the `log.level` row shows `debug`, and `~/.plexi-alpha/plexi.log` is at debug level. Bare `plexi-alpha` from CWD inside the same workspace gives the same result.
- [ ] **#308 Phase 1 — outside-workspace badge.** From a terminal pane inside a workspace, `cd /tmp` (or any path outside the workspace tree). The pane name bar shows an amber `↗ outside workspace` badge. `cd` back into the workspace — badge hides.
- [ ] **#308 Phase 1 — auto-generated `.gitignore`.** After `plexi-alpha workspace init` in a fresh dir, `.plexi/.gitignore` exists and contains `secrets.toml` and `cache/`. Re-running `workspace init` after editing `.gitignore` does NOT overwrite the user's edits.

## Breaks if (rolled up from PRs)
- **#322 (PR pending merge):** `plexi-alpha workspace init` doesn't create `.plexi/workspace.toml` with a valid UUID; or two workspaces with `[apps.<id>]` routing the same canonical secret to different friendly names return identical Keychain values; or `fallback = false` with a missing route silently falls through instead of emitting `SecretDenied { reason: "hard_missing: ..." }`; or installing an app whose manifest declares `[secrets] X = {}` (no `required` field) succeeds — it must error.
- **#308 Phase 1:** dropping `[log] level = "debug"` into `.plexi/config.toml` has no effect on the host's log level; or `plexi-alpha /path/to/workspace` doesn't adopt the path (CWD stays elsewhere, registry skips workspace apps); or `plexi-alpha /tmp` (no `.plexi/` ancestor) launches the GUI silently instead of erroring out; or `plexi-alpha workspace init` does not produce `.plexi/.gitignore` with `secrets.toml` and `cache/`; or re-running `workspace init` overwrites a user-edited `.plexi/.gitignore`; or a terminal whose CWD is outside the workspace root never shows the `↗ outside workspace` badge.
