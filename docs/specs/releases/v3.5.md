## Tier resolution at runtime
1. CLI emits `--plexi` natively → Tier 1
2. Registry has descriptor matching CLI version → Tier 2
3. Crawl `--help`, cache as inferred → Tier 3

## Release-level human verification

- [ ] Run `gh --plexi` in a Plexi terminal pane. Top 75% shows auto-UI; bottom 25% is live terminal. Click a subcommand button → command appears in terminal and executes. Output streams as normal.
- [ ] Run `cargo --plexi`. Same behavior. Click `cargo build` → build runs in terminal below.
- [ ] Run a CLI in the registry but not yet supporting `--plexi` natively (e.g. `npm`). Tier 2 descriptor loads from registry. UI renders. Click commands run in terminal.
- [ ] Run a CLI not in the registry (e.g. some obscure tool). Top of pane shows "Generating app…" briefly, then renders inferred UI marked "inferred — fidelity may vary." Cache hit on second invocation — no regen.
- [ ] Bump a tracked CLI version manually (e.g. install `gh 2.42`). Release-watcher agent (cron) detects the bump on next run, opens a PR to the registry repo with the diffed descriptor. Human merges, registry tags new `latest`.
- [ ] Long-running CLI task emits structured progress events. Plexi renders them as rich notifications: image attachment renders, structured choices are clickable, keyboard nav works.
- [ ] Rich notifications stack in the notification panel; clicking a choice in one notification routes the action correctly.
- [ ] Hot reload: edit an app's source file. Save. App reloads in-place, state preserved where possible. No full host restart.
- [ ] Capability gate: a CLI with `--plexi` claims it can write files. UI shows the capability badge in the auto-UI header. User can revoke per-app.
