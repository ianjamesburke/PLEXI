# XML video editor

Status: active

Stint: 0521, 0522, 0776, 0524, 0526, 0777, 0525

Plexi gives a person direct control at the point where an automated edit needs their eyes, ears, and taste. This applies the human-judgment commandment in [NORTH_STAR.md](../NORTH_STAR.md#the-commandments) to the multicam-edit workflow.

## Release scope

V2 targets an XML sync-review editor: open the generated sequence, inspect synchronized cameras, correct placement, remove unwanted material, and save an XML revision the existing multicam scripts can consume. The first useful release replaces the Premiere correction step in that workflow.

V3 targets creative editing on the same document: select cameras during playback, record cuts, trim, adjust crop and zoom, and render the resulting edit. These are product scope targets, not dates or promises about the next semantic-version tag. Both follow stable v1. Task metadata owns priority and dependency order; [ROADMAP.toml](../ROADMAP.toml) reports proven capability.

## Shared document

The authoritative edit document is the Premiere/FCP7-style `xmeml` used by multicam-edit. XML is the interface between the person, the editor, and automation. The editor's in-memory model derives from that document and writes changes back to it. Caches, thumbnails, and proxy indexes are disposable; no private JSON project or YAML cut list may become a competing source of edit decisions.

Support begins with the sequences generated by the skill and their touched-up Premiere exports. Publish a tested subset before accepting edits. Preserve untouched metadata, stable clip/file identities, camera track order, enabled state, audio linkage, media paths, and gaps. Unsupported constructs must produce an explicit limitation; preserving their text alone does not prove the preview understands them. Offer read-only inspection or refuse editing when round-trip semantics cannot be preserved. Disable external entity resolution.

Keep timing in integer frames with an explicit rational frame rate. No-op save, repeated nudges, and undo must not accumulate rounding through milliseconds. Initially support the normalized constant-rate workflow; reject unsupported fractional rates and retiming explicitly until fixture tests prove them.

V2 keeps the skill's acquisition/job YAML and existing final cut instructions. V3 moves creative edit decisions into the supported XML representation and updates the renderer to consume them. Acquisition settings may remain in YAML. This transition must be tested against the workflow's reader and renderer, not assumed from a successful XML parse.

## Human correction loop

Open the sequence into a camera grid, focused preview, and timeline. Provide play/pause, scrubbing, frame stepping, camera selection, linked sync nudges, clip/camera removal, and undo/redo. Every edit has a keyboard path and an agent-callable equivalent. Camera labels follow the skill's non-empty track ordering; changing that ordering refreshes labels and invalidates stale camera references in downstream work.

Preview uses a shared media clock for synchronized angles and the selected reference audio. Audio remains independent of UI paint. Bound decode queues and use proxies or reduced preview resolution when needed; a smooth host repaint rate alone does not establish synchronized playback. Measure seek latency, frame correctness, A/V drift, and responsiveness under ordinary pane/context work. The shared presentation direction lives in [realtime-app-runtime.md](realtime-app-runtime.md); qualification depends on measured behavior, without requiring unrelated runtime migrations.

Source media stays untouched. Save a named XML revision with atomic writes and permission-scoped file access. Watch the document for external agent edits: a valid change reloads a clean editor and updates the preview. If local edits are dirty or the base revision changed, retain both versions and offer reload or Save As. Invalid external XML leaves the last valid preview intact and shows the error. Bind undo and agent mutations to a document revision so stale work cannot overwrite new decisions.

Structured app events and control continue through Plexi's existing app protocol and event bus. Video/audio frames use typed binary pipes or host-owned surfaces. XML defines the edit; it does not replace Plexi's runtime transports or permission model.

## Creative editing

V3 records live camera switches and trim, crop/focus, and zoom decisions in XML. Define the representation and renderer interpretation before exposing a control. Preserve the source camera sequence while expressing the chosen output edit, so changing a cut never destroys its source alignment.

The preview and final render must agree on source frames, crop, zoom, and audio placement. Native export uses the host's scoped media.export capability, with progress, cancellation, actionable failure messages, and an audit record. Agent operations use the same document commands and revision checks as the visual editor.

## Acceptance

The V2 proof uses Ian's actual multicam shoot locally: open its generated XML, watch and listen, move a camera by one frame, undo and redo, save a new revision, and consume it through the existing grid/edit scripts. Only the intended timing changes; reopening preserves the decision. A person must audition sync and responsiveness. Automated tests use synthetic media and an anonymized fixture where needed, without committing private footage.

Qualification also exercises no-op round trips, camera deletion and relabeling, missing media, malformed XML, unsupported constructs/rates, external reload, dirty conflicts, stale agent commands, and interrupted saves. Use model invariants, scenes, realistic screenshot review, and an installed-host workflow according to [TESTING.md](../src/testing/TESTING.md).

The V3 proof adds camera cuts, crop, and a slow zoom, then compares preview and encoded output at the relevant frames with audio timing checks. A real shoot audition complements deterministic fixtures. XML interoperability and native export must pass independently.

## Boundaries

General effects, color grading, arbitrary XML dialects, and automatic editorial taste remain outside this plan. Human corrections remain first-class document edits throughout.
